Hyperledger Fabric identifies deployed chaincode by a package ID, which is a
deterministic hash of the chaincode package, together with the channel it is
committed to. There is no account address as there would be on an
account-based ledger such as Ethereum.

NOTE ON PACKAGE IDS
  The package ID is a SHA-256 over the chaincode package, so it changes
  whenever the package contents change. The ids above are the packages bound
  to the committed Sequence 4 definitions on the running network, verified on
  2026-07-26 against both the peer and the chaincode containers. Re-running
  the deploy on another machine produces different ids; read the current
  values with

    peer lifecycle chaincode queryapproved --channelID mychannel \
      --name batch-registry --sequence 4

  (queryinstalled lists every package ever installed on the peer, including
  those from superseded sequences, so queryapproved is the authoritative way
  to see which package a committed sequence actually runs.)

DEPLOYMENT MODEL
  Both chaincodes are deployed as Chaincode-as-a-Service (package type "ccaas")
  rather than through the peer's built-in Docker builder. The peer's builder
  calls a legacy Docker image-build API that Docker 29 no longer serves, which
  fails with "docker image build failed: write unix -> /run/docker.sock: broken
  pipe". Under CCaaS the chaincode runs as its own container that the peer
  dials, which is a supported Fabric 2.5 deployment mode and is unaffected.
  See readme.txt section 4 and network/deployCC.sh.
